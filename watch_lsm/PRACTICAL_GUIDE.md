# 自建智能手表生理信号基础模型（Watch-LSM）工程与实践全流程指南

本指南专门为您基于**自有预训练数据集**与**下游任务数据集**（智能手表的 PPG、3 轴 ACC $\to$ 心率、步数、睡眠等）开展基础模型的训练、微调与端侧部署提供全套工程规范与最佳实践。

---

## 1. 数据收集、清洗与结构化规范

### 1.1 传感器数据协议与采样率对齐
智能手表底层传感器通常具有不同的物理采样率：
- **PPG (光电容积脉搏波)**: 典型为 25 Hz、50 Hz、64 Hz 或 100 Hz（推荐统一重采样至 **64 Hz**，兼顾微血管形态特征与计算量）。
- **ACC (三轴加速度计)**: 典型为 25 Hz 或 50 Hz（推荐统一重采样至 **32 Hz** 或 **50 Hz**，足以捕获高达 15 Hz 的人体剧烈震动）。
- **对齐方案 (Multi-Rate Patching)**:
  - 避免将 32 Hz 的 ACC 强行插值膨胀至高频，也不要将 PPG 降频导致重搏波消失。
  - 采用 **物理时长对齐法**：以固定时间窗（如 0.25 秒）为一个 Patch Token。
  - 在 0.25 秒内：PPG 对应 16 个采样点，ACC 对应 8 个采样点 $\times 3$ 轴 = 24 个数值。经独立线性投影层映射至相同的隐藏维度 $D=128$。

### 1.2 信号质量评估与异常清洗 (SQI)
在进入预训练前，必须过滤掉严重无效数据（如脱表、传感器接触不良、极端光强饱和）：
1. **脱表检测**:
   - PPG 振幅几乎为 0 或接近 ADC 满量程上限（饱和截断）。
   - 连续 2 秒内信号标准差 $\sigma < 10^{-4}$ 时直接丢弃该窗口。
2. **运动饱和与剧烈位移**:
   - 当 ACC 模长加速度瞬时突变超过 $4g$ 且持续时间极短时，PPG 光电反射路径完全丢失，标记为不可靠区间。
3. **标准化策略**:
   - 严禁全局归一化（不同受试者、不同环境温度下的绝对光强偏置不同）。
   - 必须采用 **逐滑动窗口的 Robust Z-Score 标准化**（减去中位数/均值，除以标准差），并将极值截断在 $[-4.0, 4.0]$ 内。

## 2. 自监督预训练全流程配置

### 2.1 复合损失函数配比
自监督预训练采用三位一体的复合损失目标：
$$\mathcal{L}_{\text{Total}} = w_{\text{recon}} \cdot \mathcal{L}_{\text{MAE}} + w_{\text{cross}} \cdot \mathcal{L}_{\text{InfoNCE}} + w_{\text{spectral}} \cdot \mathcal{L}_{\text{FFT}}$$

1. **$\mathcal{L}_{\text{MAE}}$ (掩码时间序列重构损失, 权重 $1.0$)**:
   - 随机对 30% - 50% 的时间 Patch 进行遮盖（替换为可学习的 `[MASK]` Token）。
   - 迫使网络根据上下文波形推断被遮盖的脉搏与运动轨迹。
2. **$\mathcal{L}_{\text{InfoNCE}}$ (跨模态对比损失, 权重 $0.2$)**:
   - 同一时刻的 PPG 运动伪影与 ACC 肢体运动在物理上源于同一运动事件。
   - 拉近同一窗口 PPG 表征与 ACC 表征的互信息，推开不同样本间的不相关运动。
3. **$\mathcal{L}_{\text{Spectral}}$ (频域频谱保真损失, 权重 $0.1$)**:
   - 对重构的 Patch 进行实数快速傅里叶变换（rFFT），计算与真实频谱的 L1 误差。
   - 强制模型在频域保留核心心跳谐波与步频主频，避免重构信号出现“平滑过度”现象。

### 2.2 推荐算力与训练超参数
- **算力需求**:
  - 基础版模型 (参数量 ~200万 - 500万): 单张 RTX 3090 / 4090 或 A100 即可轻松训练。
  - 预训练时间：在 1,000 小时数据量下，单卡约 4 - 8 小时即可收敛。
- **超参数建议**:
  - `batch_size`: 64 ~ 128
  - `learning_rate`: $5 \times 10^{-4}$ (搭配 5 轮 Warmup 与 CosineAnnealing 衰减)
  - `weight_decay`: 0.01
  - `optimizer`: AdamW

## 3. 下游任务适配与微调指南

### 3.1 运动心率估计（抗运动伪影 HR Tracking）
- **痛点**: 跑步、快走时步频与心率主频重叠。
- **适配方案**:
  - 将预训练的 Dual-Stream Backbone 提取的全局融合特征接入 `HeartRateHead`。
  - 借助 ACC 提供的运动参考流，Cross-Attention 模块主动抑制由步频引起的虚假峰值。
  - 训练目标：L1 损失（以真实 ECG 心率为金标准，如使用胸带心率传感器或动态心电记录仪配对）。

### 3.2 步数统计与步频估计 (Step / Cadence)
- **痛点**: 假动作（如刷牙、打字、乘车颠簸）引起的误计步。
- **适配方案**:
  - 接入 `StepCountHead`，由模型直接预测 8 秒时间窗内的平均步频（Steps Per Minute, SPM）或步数增量 $\Delta \text{Steps}$。
  - 相比传统基于阈值过零点（Peak-Crossing）的经验算法，基础模型能有效区分非周期性日常手部动作与真正的规律行走。

### 3.3 睡眠分期与日常活动分类 (Sleep / HAR)
- **适配方案**:
  - 接入 `ActivityClassificationHead`，输出分类概率分布。
  - 在夜间睡眠阶段，ACC 静止接近零，PPG 呈现纯净的呼吸性心律不齐（RSA）与周期性微唤醒波形，基础模型能灵敏捕捉深度睡眠（N3）、浅睡与 REM 期的特征差异。

## 4. 智能手表端侧部署与工程优化

1. **导出 ONNX 与静态图量化**:
   - 训练完成后使用 `torch.onnx.export` 导出静态尺寸计算图（例如固定输入维度 `(1, 1, 512)` 与 `(1, 3, 256)`）。
   - 进行 Post-Training Quantization (PTQ) 转换为 INT8 模型，模型体积可压缩至 **2MB - 4MB**。
2. **端侧推理延迟优化 (面向 ARM Cortex-M / NPU)**:
   - 将 MultiheadAttention 中的 `batch_first=True` 算子通过 TensorRT 或 ONNX Runtime Mobile / TFLite 进行融合。
   - 单次前向推理耗时在可穿戴低功耗芯片上可控制在 **2ms - 5ms** 以内，支持每秒或每 2 秒触发一次低功耗推断。
